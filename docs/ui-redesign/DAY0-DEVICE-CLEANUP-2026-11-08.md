The updated signed folder Shortcut offers a third setup question: `retain` (default) or `delete-after-upload`. Existing installed copies do not change automatically. Choosing deletion transfers responsibility for the original to Budgit after confirmed storage; report parsing, categorization and financial approval can happen later. The user-facing setup explains Files confirmation and that deletion in an iCloud folder can synchronize to other devices. Share-sheet input retains files because the original cannot be safely resolved from a temporary shared copy.

The upload connection obtains a fresh receipt with exact receipt ID and hash using `verifyStorage=1`. The service rechecks the user, consent, active connection and submission ownership, decrypts the private original, checks byte length and hashes the read-back. Only that request can return version-1 `storageVerified:true` and `deviceCopyRemovable:true`. Upload and catalog receipts always set those permissions false. The existing financial `cleanupEligible` / `fullImportComplete` contract is preserved; a New or Partly digested report can authorize transfer of its device copy while remaining financially uncommitted. Storage verification invokes no parser or financial command.

Immediately before native deletion, the Shortcut re-enumerates the selected folder, requires one exact name/extension match and hashes that fresh File item. A changed or ambiguous file, unavailable server copy, invalid proof, unauthorized request, transport failure or Files refusal cannot produce a successful cleanup result. The native Delete File action uses Apple's current `WFDeleteImmediatelyDelete:false` parameter to preserve Trash/Recently Deleted behavior where supported. Its shipped description explicitly controls permanent deletion; it does not control the privacy prompt. Repeated deletion prompts depend on the owner's iOS Shortcuts setting (Allow Deleting Without Confirmation), which applies across shortcuts. Initial folder/network permission and scheduled Run Immediately setup are separate. The shortcut cannot grant those device permissions itself. The tenth new upload is checked for cleanup before the ten-upload batch bound exits. A failed local deletion retries from the next scan's fresh proof without replaying an import.

Budgit keeps the report downloadable while it is New or Partly digested. Whole-file financial handling and resolved review start the existing 30-day server timer; that retention transition is unchanged. A completion tombstone with `stored:false` cannot authorize device deletion because Budgit no longer has a retrievable original. Duplicate delivery does not restart server retention. Imported finances, history and Stage 3-disabled behavior are preserved.

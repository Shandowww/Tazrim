# תיקון תוכנית ההשלמה — חיבור הממשק למימוש הקיים

עודכן: 2026-10-28, בעקבות הנחיית Tal שלא לכתוב מחדש פיצ׳רים קיימים. מסמך זה מתקן את תוכנית החלפת הממשק ואת סדר העבודה; הוא גובר על רשימות “pending” ועל הוראות ההמשך ההיסטוריות. הוא אינו מתחיל את הפרויקט מחדש.

## התוצאה והגבולות

להשלים את ממשק React באמצעות היכולות שכבר קיימות ב-Budgit. שרת Node, הנתונים, כללי החישוב, הפענוח, השמירה וההרשאות נשארים הבסיס. React מחליף תצוגה וקלט; הוא אינו מחליף את השרת. אין יבוא של תשתית בנקאית, מסד נתונים או API של Tazrim. ממשקי הדוחות הפנימיים של Budgit אינם חיבור ישיר לבנק.

שומרים את העבודה שנבדקה. לא משכתבים מסכים שכבר פועלים רק לשם אחידות. לא מוסיפים תמיכה חדשה בפורמטים, אוטומציות, שירותים או יכולות פיננסיות כדי לסגור משימת החלפת UI. מגבלה שהייתה קיימת נשארת מגבלה מתועדת; היא אינה פיצ׳ר חדש שחייבים לפתח לפני פרסום.

## כלל יישום מחייב

לפני כל שינוי מציינים את הפעולה הקיימת, קובץ המימוש והבדיקה שלה, ואת חיבור ה-UI שחסר. סדר ההעדפה: קריאה למודול/פקודה קיימים; מתאם קלט ותצוגה קטן; ואם ההתנהגות קשורה ל-DOM — חילוץ מצומצם של אותה התנהגות למודול משותף ששני הממשקים צורכים. אין לכתוב מנהל תהליך מקביל עם כללים חדשים. אין חילוץ גורף של כל האפליקציה.

בדיקת שוויון עם ההתנהגות המקורית קודמת להסרת כפילות. שומרים גם על נתוני הטיוטה, קבלות המקור, סדר האישורים, הרשאות, שגיאות והתאוששות — לא רק על הסכום הסופי. בדיקות המימוש החדש לבדן אינן הוכחת שוויון. שינוי שרת מותר רק לפער תאימות או אבטחה מוכח, עם תיעוד הסיבה ובדיקת תאימות לממשק המקורי; לא למען תהליך React מקביל.

### פערים קונקרטיים לטיפול ראשון

1. **סיווג אופציונלי:** `inboxBuild` המקורי מעביר `deferCategories=true`; `prepareNativeCardReport` החדש מעביר `false`. זו סטייה מהזרימה הקיימת, לא צורך בפיצ׳ר חדש. להחזיר אפשרות לדחות סיווג, תוך שמירת בדיקות כפילות וסכומים, ולהוכיח זאת מול המקור.
2. **תזמור וטיוטות:** המקור שומר קבוצות בגרסה 1; מתאמי React מגבילים כרגע לקובץ יחיד ולקבוצות נתמכות צרות. לחלץ/לחבר את התנהגות המקור בלי להמיר או לדרוס החלטות שמורות ובלי לפתח פורמט טיוטה חדש. גם מגבלת מחזור פעילות אחד לקובץ במסלול החדש צריכה השוואה להתנהגות המקור, ולא הרחבה אוטומטית.
3. **מעבר לממשק המקורי:** `legacyBudgetHref` מעביר רק `budget`, ולא פעולה, דוח או תקופה. קישור כללי אינו הוכחת חיבור לפעולה. למפות יעד והקשר מדויקים ולהגן על טיוטות במעבר ובחזרה. קישורים זמניים נשארים זמינים עד שהחיבור הושלם; אין להסירם כדי להסתיר פער.
4. **ניקוי מקורות אחרי גיבוי:** `server/report-store.mjs` מחזיר `cleanupEligible:false`. אין להתייחס לניקוי כזה כיכולת קיימת שחייבים לממש מחדש; הוא מחוץ להשלמת UI זו אלא אם אימות הבסיס יראה מימוש קיים. מחיקת מקור שלא נקלט וביטול קליטה הן פעולות נפרדות עם כללים קיימים.

אלה ממצאי קריאת קוד, לא תיקוני התנהגות שבוצעו בשינוי התוכנית.
